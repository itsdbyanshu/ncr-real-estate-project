NCR Real Estate Analytics + GenAI

Your personal build roadmap — scrape rental listings, clean and load them into Snowflake and Neon, automate it daily, put a live dashboard and a GenAI agent in front of it, then ship the whole thing as a website.

Project Setup From Zero

VS Code, local machine

gitvenvpython3

Create the project skeleton before writing any real logic, so every later step has a home.

  1. Create a folder, e.g. ncr-real-estate-project, and open it in VS Code.
  2. Initialize git: git init, create a GitHub repo, connect it with git remote add origin <repo-url>.
  3. Create a virtual environment so dependencies stay isolated: python -m venv venv, then activate it.
  4. Create a .gitignore (ignore venv/, .env, __pycache__/) — this matters because Step 1 onward involves real credentials that must never hit GitHub.
  5. Create a requirements.txt — you'll add to it as you install libraries later.
ncr-real-estate-project/ ├── etl_pipeline.py ├── agent.py ├── app.py ├── requirements.txt ├── .gitignore ├── .env ├── templates/ │ └── index.html └── .github/ └── workflows/ └── main.yml

Why it matters — every later step just fills in a file that already exists, instead of you restructuring mid-project.

Identical Databases on Snowflake and Neon

Snowflake web UI (Snowsight) + Neon console

SnowflakeNeon

Create the two databases that will hold the same cleaned data, with matching schemas so Power BI can later point at either one without changes.

  1. Start a free Snowflake trial. Create database NCR_REAL_ESTATE, table RENTAL_LISTINGS with columns: title, rent_price, sqft, bhk, sector, price_per_sqft, scraped_at.
  2. Sign up for Neon, create a project, and build a matching Postgres table with the same column names and types.
  3. Save both sets of connection credentials in your local .env — never hardcode them.

Why it matters — matching schemas now is what makes the later Snowflake → Neon switch (Step 6.5) a five-minute config change instead of a rebuild.

Build the Scraper Script

Jupyter Notebook → etl_pipeline.py in VS Code

requestsbeautifulsoup4selenium (if needed)

Write the extraction logic that pulls raw rental listing data from 99acres or MagicBricks.

  1. pip install requests beautifulsoup4, add to requirements.txt.
  2. In a notebook, fetch one listings page and inspect the HTML (Chrome DevTools → Inspect) to find the right tags/classes.
  3. Write scrape_listings(pages=N) to loop pages and extract Title, Rent Price, SqFt, BHK, Sector into a list of dicts.
  4. Test on 2–3 pages first. Sites change markup and rate-limit — add a small time.sleep() between requests.
  5. Once reliable, move the working function into etl_pipeline.py.

Why it matters — notebooks let you re-run one cell after a broken selector instead of re-running the whole script.

Clean and Transform With Pandas

Notebook → etl_pipeline.py

pandas

Turn the raw scraped data into a clean, analysis-ready DataFrame.

  1. pip install pandas, add to requirements.txt.
  2. Load scraped dicts into a DataFrame: pd.DataFrame(raw_data).
  3. Strip ₹/commas from prices → integers; extract numeric SqFt and BHK.
  4. Drop rows with missing price (df.dropna(subset=['rent_price'])); add price_per_sqft and scraped_at.
  5. Wrap it all as one function, clean_data(raw_df) → clean_df.

Why it matters — one isolated cleaning function means Step 4's dual-write can call it once and feed the same clean DataFrame to both databases — no duplicated logic, no drift.

Feed Cleaned Data to Both Neon and Snowflake

etl_pipeline.py in VS Code

snowflake-connector-pythonpsycopg2sqlalchemy

Write the loading logic that pushes the same clean DataFrame into both databases.

  1. pip install snowflake-connector-python psycopg2-binary sqlalchemy.
  2. load_to_snowflake(clean_df) using write_pandas().
  3. load_to_neon(clean_df) using SQLAlchemy's to_sql() against your Neon connection string.
  4. Wrap each in its own try/except with a clear log message — so one silent failure doesn't let the two DBs drift apart unnoticed.
raw = scrape_listings()
clean = clean_data(raw)
load_to_snowflake(clean)
load_to_neon(clean)

Why it matters — after a manual run, always confirm row counts match in both Snowsight and the Neon SQL editor before moving to automation.

Automate the Pipeline Daily via GitHub Actions

.github/workflows/main.yml, pushed to GitHub

GitHub Actionscron

Make etl_pipeline.py run on its own every day, without you triggering it.

  1. Push the project (excluding .env) to GitHub.
  2. In repo Settings → Secrets → Actions, add each .env value as a GitHub Secret.
  3. Write main.yml: trigger on a daily cron schedule, checkout, set up Python, install requirements.txt, run python etl_pipeline.py with secrets as env vars.
  4. Push and check the Actions tab — trigger manually once (workflow_dispatch) rather than waiting a day to find out it's broken.

Why it matters — only automate once Steps 1–4 already work reliably by hand — debugging a scraper and a cron job at once is much harder than debugging them apart.

Build the Power BI Dashboard on Snowflake

Power BI Desktop → Power BI Service

Power BI DesktopDAX

Build a live dashboard that queries Snowflake directly, updating automatically as new data lands.

  1. Get Data → Snowflake → enter your credentials.
  2. Choose DirectQuery mode, not Import — the dashboard queries Snowflake live.
  3. Build a sector heat map, a price trend line, BHK/sector filters, price-per-sqft cards.
  4. Publish to Power BI Service → File → Embed report → Publish to web, and save the <iframe> snippet for Step 9.

Build the GenAI Agent on Neon

agent.py, tested in the terminal

langchainlangchain-groqsqlalchemy

Build an agent that answers plain-English questions about the rental data by querying Neon directly.

  1. pip install langchain langchain-community langchain-groq sqlalchemy psycopg2-binary.
  2. Get a free Groq API key, store it in .env.
  3. Set up LangChain's SQLDatabase + SQLDatabaseToolkit pointed at your Neon connection string — the same pattern as your WORLDCUP DATABASE project.
  4. Write a strict system prompt limiting the agent to the RENTAL_LISTINGS table only.
  5. Test several questions in the terminal first, including out-of-scope ones it should refuse.

Build the Content and Integrate the Dashboard + Agent

app.py + templates/index.html

flaskHTML/CSSfetch

Fill in the skeleton — paste in the live dashboard, wire up a working chat interface to your agent.
